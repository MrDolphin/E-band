## 2. 已完成能力

目前已经形成一条统一的 FMCW 雷达处理链：

```text
雷达配置
  -> FMCW 波形与有限 CPI
  -> 合成目标 / IQ 回放 / E310 数据源
  -> Chirp 同步
  -> 数字去斜
  -> 距离 FFT 与多普勒 FFT
  -> 2D CA-CFAR 与目标聚类
  -> 距离、径向速度、SNR 和可信度
  -> 最新帧控制器
  -> 中文 GUI、文件输出和命令行分析
```

所有数据源都进入同一个 `FmcwProcessor`。合成目标真值不会绕过信号处理链直接生成检测结果或热力图。

首版保持单接收通道，因此不输出伪造方位角。GUI 明确显示“单 RX：方位角未测量”，目标在半圆雷达图的 0° 参考线上展示。

### 3.1 Task 1：配置、数据模型与物理量契约

**新增能力**

- 建立独立的 `sdr_loopback.radar` 包，新增不可变的 `RadarConfig`、`SyntheticTarget`、`RadarTarget`、`RadarDiagnostics`、`RadarCapture` 和 `RadarFrame`。
- 将 76 GHz、30 MSPS、20 MHz、128/16 μs、64 Chirp 等默认参数集中到 `RadarConfig`，避免 CLI、GUI 和处理器各自维护重复常量。
- 由配置统一计算有效样点数、单 Chirp 样点数、CPI 样点数、波长、Chirp 斜率、距离分辨率、最大无模糊速度和速度分辨率。

**关键优化与边界处理**

- 修正速度公式中的慢时间奈奎斯特因子，确保最大速度和速度分辨率与 Chirp 周期、Chirp 数量一致。
- 对采样数必须为整数、FFT 长度必须覆盖有效样点等错误配置执行提前失败，避免在 FFT 阶段才出现难以定位的异常。
- NumPy 数组字段统一转换为数组并验证维度；数组字段不参与数据类自动相等比较和详细字符串输出，避免 NumPy “真值不明确”异常和巨量日志。
- 冻结配置和帧模型，防止处理链运行中参数被意外修改。

**结果**

- 默认配置精确得到 3840 个有效样点、4320 个单 Chirp 样点和 276480 个 CPI 样点。
- 聚焦与完整测试通过，独立复审通过。
- 提交：`5428ac4 Add FMCW radar configuration models`。

### 3.2 Task 2：FMCW 波形与时域目标仿真

**新增能力**

- 新增 FMCW 单 Chirp 和完整 CPI 生成器；有效区为单位幅度复数上扫频信号，空闲区为精确零值。
- 新增时域合成目标仿真器，根据距离、径向速度和 SNR 生成 RX IQ，而不是直接生成检测结果。
- 支持多目标叠加、直达泄漏、静态杂波和复高斯噪声，并把合成真值仅保存在 `RadarCapture` 中供测试验收使用。

**关键优化与边界处理**

- 目标传播时延采用分数样点计算，不把距离粗暴舍入到整数样点，避免近距离目标产生量化偏差。
- 明确定义正径向速度对应的慢时间相位方向，使仿真、FFT 速度轴和最终显示方向一致。
- 使用固定随机种子保证 IQ 完全可重复，同时逐帧推进种子时仍可生成不同噪声样本。
- 多目标、泄漏和静态杂波都在时域 IQ 中真实叠加，处理器无法通过读取真值“作弊”。

**测试场景**

- 单 Chirp 带宽与持续时间、精确空闲区、64 Chirp CPI 结构；
- 分数时延、正速度相位方向、多个目标叠加；
- 泄漏与静态杂波、噪声 RMS 与目标 SNR；
- 相同种子产生相同 IQ。

**结果**

- 聚焦 9/9，完整 14/14，复审通过。
- 提交：`ba75c33 Add FMCW waveform and target simulator`。

### 3.3 Task 3：Chirp 同步与距离-多普勒处理

**新增能力**

- 新增 `ChirpSynchronizer`，同时支持已知起点和相关搜索两种同步模式。
- 新增共享的 NumPy 处理链：`RX × conj(TX)` 数字去斜、快时间/慢时间 Hann 窗、距离 FFT、多普勒 FFT 和可选慢时间均值杂波抑制。
- 根据采样率、Chirp 斜率、波长和 Chirp 周期生成物理距离轴、速度轴及半谱矩阵。
- 诊断信息增加同步分数、削顶比例、RMS、峰值、噪声底和处理时间。

**关键优化与复审修复**

- 相关搜索只扫描实测 RX IQ 的有限前缀，随后验证全部 64 个 Chirp 的间隔和有效区/空闲区能量，不再错误地对 TX 参考自身搜索。
- `RadarCapture` 增加经过验证的 `chirp_start_sample`，允许 RX 含同步前缀或尾部余量，同时保证选出的完整 CPI 有效。
- 距离与多普勒 FFT 长度必须是正的 2 的幂，并分别覆盖有效样点数和 Chirp 数量。
- 极端但有限的输入在相关和能量计算前提升为 `complex128/float64`；任何溢出后的非有限指标都会明确抛出同步错误。
- 保持延迟上扫频信号的符号约定，将 FFT 的物理负频半区正确映射为递增正距离，避免距离轴反向。
- 处理器明确不读取 `truth_targets`，Task 3 阶段暂不制造目标列表，为后续检测器保留清晰边界。

**结果**

- 最终聚焦 17/17，完整 26/26，复审问题全部关闭。

### 3.4 Task 4：二维 CFAR、目标聚类与可信度

**新增能力**

- 实现仅依赖 NumPy 的二维 CA-CFAR，直接在距离-多普勒线性功率矩阵上工作。
- 使用积分图快速计算训练单元功率和数量，默认多普勒训练/保护单元为 `4/1`，距离方向为 `8/2`。
- 加入八邻域局部峰值、八连通聚类、确定性最强单元保留、局部 SNR 估计和置信度计算。
- 检测结果按 SNR 降序排列并生成帧内 `T01`、`T02` 等 ID；单 RX 目标始终保持 `azimuth_deg=None`。

**关键优化与复审修复**

- 近距离 CFAR 不再整体排除前两个有效距离 bin：仅保护 DC bin，bin 1 和 bin 2 使用远端单侧训练单元，因此约 7 m 和 14 m 的目标仍可检测。
- 对窄矩阵和边缘训练窗口进行边界夹紧，并要求最小训练单元数量，修复近距离索引越界。
- 使用暴力求和参考实现逐单元验证积分图的训练和计数结果，防止快速算法悄然产生阈值偏差。
- 局部峰值与原始功率的全部八邻域比较；相邻等高峰采用字典序确定性决胜，避免平台相关结果。
- 检测目标限制在 `max_display_range_m` 内，但完整热力图和物理坐标轴不被截断。
- 静态杂波抑制改为显式可选，默认保留静止目标，等待 Task 8 使用空场背景标定处理固定杂波。
- `RadarFrame` 增加帧号、诊断帧号、目标时间戳、bin 边界和物理坐标一致性校验。

**关键数值测试**

- 静止目标、移动目标、双目标、同距离不同速度、弱目标；
- 十个固定种子的纯噪声 CPI，无持续或相邻 bin 假警；
- 强近距泄漏加远处移动目标，无重复聚类；
- 20 dB 控制夹具的 SNR 误差不超过 3 dB；
- 距离和速度误差均不超过一个物理 bin。

**结果**

### 3.6 Task 6：最新帧控制器与并发关闭边界

**新增能力**

- 新增一次性 `RadarController` 后台工作线程，统一管理数据源打开、采集、处理和关闭。
- GUI 交接使用容量为 1 的队列：新帧到来时淘汰旧帧并累计丢弃计数，避免显示端落后后形成不断增长的延迟。
- 状态快照记录运行状态、原始错误、关闭错误、采集/处理耗时、超时次数和显示丢帧数。

**关键优化与复审修复**

- `stop()` 使用单一绝对截止时间，超时后不再执行同步关闭或额外等待，确保调用方不会因阻塞的硬件 `close()` 无限卡住。
- 数据源生命周期显式建模为 `NOT_OPEN`、`OPENING`、`OPEN`、`CLOSE_REQUESTED`、`CLOSED`，解决打开尚未完成时提前关闭的竞态。
- 关闭工作可交给守护清理线程；工作线程和清理线程竞争时仍保证真实 `close()` 最多执行一次。
- 将处理错误与关闭超时分开保存，避免真正的采集/算法根因被“关闭超时”覆盖。
- 修复 `Thread.start()` 失败后的状态和清理；并发 start/stop 不再可能对尚未启动的线程调用 join。
- 修复终态竞态：停止线程不能在工作线程已经写入 `running=False` 后把状态重新覆盖为 true。
- 并发测试使用 Event、受控锁所有者元数据和 `finally` 回收，不使用概率性 sleep，能够确定性复现旧实现的竞态。

**测试规模说明**

- 最终聚焦 13/13，完整 67/67。
- 测试/生产比例高于 1:1，主要来自五类独立并发边界所需的受控 fake source、事件握手和失败清理代码；没有删除截止时间、阻塞关闭、打开中停止、启动失败或终态竞态测试来压缩比例。

- 76 GHz 空口端观察到由 9.5 GHz 八倍频 LO 与约 900 MHz IF 形成的上下边带，Max Hold 可填满约 20 MHz；
- RX 板 RX_Q 能同时看到稳定 DDS 和约 20 MHz FMCW 频带，证明 TX 板、PA、两只喇叭、空间链路、RX LNA/混频器和 RX_Q 输出均已打通；
- RX.txt 已采用接收预设：SPI2 `0x1A = 0xFC`，I/Q 两级基带增益增强位均已置位，LNA 四级偏置也已使用 RX 配置，不再盲目提高芯片偏置。

随后对 E310 原始 IQ 做时频轨迹分析。20 MHz、TX `-30 dB`/0.40 时扫频轨迹仅高于瞬时噪声约 1.5–1.7 dB；把 E310 RX 增益从 20 提到 50 dB 只放大噪声。1 MHz 和 200 kHz 诊断带宽的轨迹分别达到约 18 dB 和 19 dB，证明同步失败来自宽带链路预算，而不是端口、扫频方向或共轭模型。保持 20 MHz 但把 Chirp 延长到 1 ms 仍无改善，也排除了“仅靠延长积累时间即可恢复”的假设。

最终采用小步、安全增益法恢复 20 MHz 正式链路：

- 两喇叭面对面 35 cm 时，TX `-25 dB`、数字幅度 0.40、RX 20 dB 连续 3/3 帧成功；同步分数为 0.5196–0.5238，相位一致性为 0.9950–0.9968，峰值约 -37.5 dBFS，无削顶；
- 约 8 m、边长 20 cm 角反场景在 TX `-20 dB`、数字幅度 0.40、RX 20 dB 下连续 3/3 帧成功；最终复采同步分数为 0.1454–0.1533，相位一致性为 0.9799–0.9880，峰值约 -38.5 至 -39.0 dBFS，无削顶；
- 目标落在 `7.026 m` 网格单元，最终帧 SNR 为 29.67 dB。该值是 20 MHz 带宽和 4096 点 FFT 下的距离量化结果，不能解释为精确测得 7.026 m；
- 移走角反后，正式相关同步失败。对保存的空场 IQ 强制离线对齐仅用于比较时，同一距离单元功率为 -79.38 dB、SNR 20.22 dB、相位一致性 0.81；角反场对应 -71.29 dB、SNR 27.61 dB、相位一致性约 0.96–0.98，角反带来约 8.1 dB 的功率提升；
- 未继续提高到已授权上限 `-15 dB`，因为 `-20 dB` 已稳定通过且无削顶。

最终三份角反原始 Capture 保存在 `python_sdr_loopback/artifacts/hardware/corner-8m-tx20-raw/`，空场原始 Capture 保存在 `python_sdr_loopback/artifacts/hardware/empty-8m-tx20/raw-empty.npz`。这些 artifacts 保持未跟踪，不进入 Git 提交。速度仍标记为 `velocity_trusted=False`，因为本次验收目标为静止角反且单 RX 系统不能提供可信方位角。
